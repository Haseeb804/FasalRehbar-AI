# PakAgri — Complete Database Schema

This is the real schema, generated by actually running `python manage.py migrate` against a live
PostgreSQL 16 database (matching your `pakagri` / `postgres` setup) and dumping it with `pg_dump`.
The raw SQL is in `pakagri_schema.sql` in this same folder — this document is a readable summary of it.

**You do not need to run this SQL file yourself.** `python manage.py migrate` creates all of this
automatically from the Django models. This file exists so you can see exactly what gets created,
for your own understanding or documentation purposes.

## Tables created (23 total)

Django's own tables (auth, sessions, admin, content types) plus this project's 9 app tables:

| Table | Purpose |
|---|---|
| `core_crop` | Mango / Onion / Sugarcane — the 3 crops |
| `core_disease` | All 29 diseases across the 3 crops (populated by `sync_ml_metadata`) |
| `core_faq`, `core_contactmessage`, `core_notification`, `core_activitylog`, `core_feedback` | Site content/support features |
| `detection_scanimage` | Every image a user uploads |
| `detection_prediction` | The AI's result for each scan (crop, disease, confidence, model agreement, Grad-CAM image) |
| `recommendation_recommendation` | Treatment/prevention advice + the RAG-generated bilingual content |
| `recommendation_userfeedback` | "Was this helpful?" feedback per recommendation |
| `history_predictionhistory` | Historical record/audit trail of predictions |
| `accounts_profile` | Extended user profile (phone, farm name, preferred language, etc.) |
